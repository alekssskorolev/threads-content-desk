Подготовь JSON-файл с постами для Threads. Верни готовый файл posts.json в UTF-8. Никакого Markdown, комментариев, HTML и пояснений внутри файла.

Структура:
{
  "kind": "threads-posts",
  "version": 1,
  "posts": [
    {
      "id": "post-001",
      "text": "Первый текст поста",
      "continuation": "Продолжение поста"
    },
    {
      "id": "post-002",
      "text": "Пост без продолжения"
    }
  ]
}

Правила:
1. text — обязательная непустая строка, не более 500 символов Unicode.
2. continuation — необязательная непустая строка до 12000 символов. Если продолжения нет, не добавляй поле. Это предел импорта сайта, а не гарантия лимитов Threads: текст должен подходить выбранному способу публикации.
3. id — обязательный уникальный стабильный идентификатор: 1–48 латинских букв, цифр, дефисов или подчёркиваний. Используй post-001, post-002 и т. п. В следующих партиях продолжай нумерацию: post-013, post-014, а не начинай заново.
4. Не меняй текст уже загруженного ID. Для новой версии используй новый ID. Повторный импорт тех же ID с теми же текстами пропускается без дублей; совпавший ID с другим текстом отклоняет весь файл.
5. Переносы строк внутри JSON-строк записывай как \n. Кавычки экранируй стандартными средствами JSON.
6. Не добавляй персонажа, город, даты или время публикации в файл. Пользователь выбирает персонажа на сайте перед загрузкой; порядок постов совпадает с порядком в массиве.
7. Не используй длинные тире U+2014 и U+2013. Вместо них - обычный короткий дефис '-' или естественная пунктуация. Текст человечный, конкретный, без шаблонных заходов и выдуманного личного опыта.
8. Один файл — от 1 до 100 постов, не более 200 КБ. Тексты — обычный текст, без HTML/Markdown-разметки интерфейса. Не включай ключи, пароли или другие секреты.

Перед генерацией запроси у пользователя тему, язык, тон и количество постов, если они ещё не заданы.
