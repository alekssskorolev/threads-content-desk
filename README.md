# Threads Desk

Лёгкий сайт для публикации подготовленных текстов в Threads: персонажи,
региональные часы, копирование текста и отметки «Опубликовано».
Без сборки и внешних UI-библиотек. Посты не публикуются автоматически.

## Текущий интерфейс

- Полоска персонажей прокручивается горизонтально. Кнопка **+** всегда рядом.
- Для нового персонажа задаются имя и город/часовой пояс IANA. По умолчанию — Москва.
- У трёх встроенных аккаунтов — дата Нью-Йорка и часы Нью-Йорка/Лос-Анджелеса, без Москвы.
  У нового персонажа — дата и часы только выбранного города. Часы учитывают DST.
- Вся активная очередь показывается без временных слотов и деления на «сегодня/будущее».
  Время публикации не назначается; исторические `scheduled_slot` в сохранениях не удаляются.
- Нажатие на первый блок или продолжение копирует именно этот текст.
- Между блоками есть широкая нейтральная область: 48 px высотой на телефоне,
  32 px шириной на компьютере. Внутренней прокрутки продолжения больше нет.
- Галочка относится ко всему посту и перемещает его в «Опубликованные».
- Нижних разделов «Дополнительные функции», «Общая статистика» и
  «Прежние короткие черновики» нет. Сами старые тексты и метрики сохранены.
- Настройки облака и резервная копия доступны через **⋯** в верхней полоске.
  Ранее включённые короткие посты остаются в очереди; опубликованные доступны в архиве.

## Добавить персонажа и загрузить посты

1. Нажмите **+**, введите имя и выберите город. Для другого города можно указать
   IANA-идентификатор, например `Europe/Moscow` или `Asia/Tokyo`.
2. Откроется мини-страница. Нажмите **Инструкция для чата** и скопируйте инструкцию
   в чат, где готовятся тексты. Она включает уже занятые ID выбранного персонажа.
3. Полученный файл JSON выберите через **Загрузить JSON**.
4. Проверьте имя персонажа, число новых постов и дублей. Нажмите **Добавить посты**.
5. При подключённом облаке дождитесь статуса **Облако: синхронизировано**.

Файл не создаёт персонажа сам: всегда загружается в мини-страницу,
из которой был открыт выбор файла, даже если во время чтения файла сменить вкладку.
Проверка выполняется целиком до изменения данных. Импорт дополняет библиотеку,
не удаляет посты и не меняет уже опубликованные тексты.

### Формат файла

```json
{
  "kind": "threads-posts",
  "version": 1,
  "posts": [
    {"id": "post-001", "text": "Первый текст", "continuation": "Продолжение"},
    {"id": "post-002", "text": "Пост без продолжения"}
  ]
}
```

- `id`: уникальный стабильный ID в пределах одного персонажа, 1–48 латинских букв,
  цифр, дефисов и подчёркиваний; `__proto__`, `constructor`, `prototype` запрещены.
- `text`: непустая строка до 500 символов Unicode.
- `continuation`: необязательная непустая строка до 12000 символов. Это лимит импорта,
  не гарантия доступности такой длины в Threads. Проверяйте выбранный способ публикации.
- Один файл: 1–100 постов, до 200 КБ, UTF-8. Порядок очереди совпадает с порядком массива.
- Повторный ID с теми же текстами пропускается. Если текст отличается — весь файл
  отклоняется, включая другие новые записи. Для новой версии текста нужен новый ID.
- У разных персонажей одинаковые `post-001` разрешены: внутренние ID имеют namespace.
- Следующие партии продолжают нумерацию, а не начинают её сначала.
- Имена персонажей, город, ключи и времена публикации в файл добавлять не нужно.
- HTML выводится как обычный текст, не исполняется.

Готовые файлы: [инструкция](posts-import-instruction.txt) и
[пример JSON](posts-import-example.json). На сайте инструкция дополнительно содержит
имя и занятые ID именно выбранного персонажа. Секретного ключа в ней нет.

## Облако и приватность

Без подключения данные хранятся только в localStorage этого браузера.
После подключения — в личной YDB через защищённую Cloud Function.
Новые персонажи, выбранные города, импортированные тексты и отметки синхронизируются.
Код и встроенные тексты остаются публичными на GitHub; частная библиотека хранится
в облачной базе и локальном кеше, не коммитится в репозиторий.

Секретный ключ хранится отдельно от данных и не входит в резервные копии.
Любой обладатель ключа сможет читать и менять данные: это однопользовательская схема,
а не независимые аккаунты. Не отправляйте ключ, приватную ссылку или `client-config.json`
в чат и не публикуйте на GitHub. Вход в Яндекс на самом сайте не нужен.

На каждом новом браузере требуется однократное подключение. Ссылка для второго
браузера доступна через **⋯ → Ссылка для другого браузера**. URL-фрагмент подключения
не отправляется HTTP-серверу; страница сразу очищает адрес.

Чтение происходит при открытии/возврате во вкладку и раз в 30 секунд, пока вкладка
видна. Изменения отправляются после короткой задержки. При потере связи сохраняется
локальная очередь, которая переживает перезагрузку и отправляется после восстановления.
Очистка браузера до отправки уничтожает неотправленные изменения — следите за статусом.
Изменения разных записей, персонажей и импортированных постов объединяются по ID.
Конфликты одной записи требуют явного выбора, не перезаписываются молча.
Не редактируйте офлайн в нескольких вкладках одного браузера одновременно.

Текущая простая API-схема хранит небольшое общее состояние одной строкой: запрос
до 512000 байт. Добавление ограничено примерно 490 КБ общего состояния с запасом,
а не размером базы 1 GB. При превышении интерфейс откажет без частичной загрузки.
Для больших библиотек потребуется перейти к отдельным строкам постов в YDB.
Сервисы тарифицируются по использованию; бесплатность не гарантируется.
Подробности установки: [cloud/README.md](cloud/README.md).

## Существующие данные

Ключ `threads-desk-v1`, формат резервной копии `threads-desk-backup`, `version: 1`
и ID встроенных постов сохранены. Тексты встроенных постов не переписаны.
Дополнительные `custom_people` и `custom_posts` входят в те же резервные копии.
Старые копии без них по-прежнему читаются. Восстановление старой копии — явная
замена всего пользовательского состояния, в том числе новой библиотеки.

История метрик, ссылки и прежние поля не удалены из сохранений, но интерфейса
импорта Collector/CSV/описаний/резерва в этой версии нет. Адаптеры в `integration/`
оставлены в репозитории. Автосбора статистики, входа в Threads и автопубликации нет.
Сам факт облачного хранения не даёт AI-агенту доступа к приватной базе.

При изменении схемы не переиспользуйте опубликованные ID и не добавляйте продолжение
к уже опубликованному посту: создавайте новый ID. Берегите резервные копии — в них
могут быть ссылки, частные тексты и статистика.
Псевдонимы и AI-аватары не следует выдавать за реальных медицинских специалистов;
сайт не выполняет медицинскую диагностику и не назначает лечение.

## Проверка

- `test/cloud/test_api.py`: локальные тесты API на имитации транзакций, нужен ydb SDK.
- `test/cloud/test_installer.py`: сценарии CLI-установки без реального облака.
- `test/cloud/test_browser.cjs`: регрессия синхронизации в отдельных браузерах.
- `test/cloud/test_people.cjs`: создание профиля/города, JSON-предпросмотр, повторы,
  защита существующих текстов, синхронизация библиотеки, реальные touch-жесты.

Браузерные тесты запускаются с локальным HTTP-сервером на 127.0.0.1:8765
и имитируют API. Реальный секретный ключ в тестах не используется.
Старые тесты расписания/статистики относятся к прежним версиям интерфейса.
