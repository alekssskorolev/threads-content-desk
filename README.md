# Threads Desk

Версия 3: сверху персонажи и свёрнутая общая статистика по трём аккаунтам. Нажатие на текст копирует пост; увеличенная область «Опубликовано» перемещает карточку в нижний сворачиваемый раздел. Служебные кнопки скрыты под очередью.

Статический сайт без сборки и внешних библиотек: три автора, 27 публикаций на три дня + 3 резервных поста.

## Что работает
- Переключение авторов с адресами `#A`, `#D`, `#E`.
- Очередь неопубликованных постов в порядке дней, копирование нажатием на текст (с клавиатуры — Enter или пробел).
- Опубликованные посты находятся внизу. Резерв и Instagram bio — в дополнительных функциях.
- Отметка публикации, фактическое время и ссылка на пост.
- История измерений: просмотры, лайки, ответы, репосты, цитирования, поделиться, переходы.
- Резервные копии JSON и экспорт истории CSV.
- Прямой импорт одного или нескольких archive.json из Threads Collector links-v2; также поддерживается threads-metrics v1. Сопоставление по ID опубликованного поста. Формат: `parser-example.json`.

## Запуск
Откройте `index.html` в браузере. Для устойчивой работы буфера обмена и хранения рекомендуется HTTPS (GitHub Pages) или локальный HTTP-сервер. При запрете буфера используйте ручное выделение текста.

## GitHub Pages
1. Создайте публичный репозиторий, например `threads-content-desk`.
2. Загрузите `index.html`, `posts.json`, `.nojekyll`, `README.md`, `parser-example.json` в корень основной ветки.
3. Settings → Pages → Build and deployment → Source: Deploy from a branch.
4. Выберите основную ветку (обычно `main`) и папку `/ (root)`, затем Save.
5. Дождитесь завершения публикации. Адрес сайта GitHub покажет в Settings → Pages.

Никаких токенов и секретов в коде нет. Сайт публичный; любой посетитель может прочитать тексты постов.

## Хранение и приватность
Без подключения облака статистика и отметки находятся только в localStorage этого браузера и между устройствами не синхронизируются. После подключения Яндекс Cloud они сохраняются в личной базе YDB через защищённую функцию. Не публикуются в GitHub. Ключ доступа хранится в браузере отдельно от отметок и не включается в резервные копии. Очистка данных сайта удалит ключ из этого браузера, но не облачную базу: понадобится повторное подключение.

### Подключение облака

1. Откройте приватную ссылку подключения в том же браузере и профиле, где сохранились отметки. Либо используйте «Дополнительные функции → Подключить облако» и файл `client-config.json` из своего Cloud Shell.
2. На странице подключения дайте согласие на облачное хранение и нажмите «Проверить и подключить».
3. При наличии локальных отметок подтвердите перенос на основном сайте. Перед этим автоматически сохраняется локальная копия, доступная через «Копия до подключения». В непустую базу новые записи объединяются; конфликты требуют решения владельца, а не молчаливой перезаписи.
4. Дождитесь статуса «Облако: синхронизировано».
5. В другом браузере откройте ту же приватную ссылку и подключитесь. Он загрузит облачные отметки. Для переноса доступа также есть кнопка «Ссылка для другого браузера» в дополнительных функциях.

Приватная ссылка содержит секретный ключ: не отправляйте её в чат, не публикуйте и не делитесь с другими. Параметры передаются через URL-фрагмент, который браузер не отправляет HTTP-серверу; страница сразу очищает адрес. Не сохраняйте такую ссылку в общедоступных заметках/истории. Никогда не вводите здесь пароль от Яндекса.

Обновление выполняется при открытии, возврате во вкладку и раз в 30 секунд, пока вкладка видима. Изменения отправляются с короткой задержкой. При отсутствии связи они остаются в локальной очереди, переживают перезагрузку и отправляются после восстановления связи. Это не гарантия резервирования: очистка браузера до отправки уничтожит неотправленные изменения. Проверяйте статус облака и экспортируйте важные данные.

Изменения разных постов объединяются; разные изменения одного поста приостанавливают запись и требуют выбора. «Сохранить мои» и «Принять облачный вариант» относятся только к конфликтующим записям, не отменяют независимые изменения других постов. Перед разрешением конфликта сохраняется локальная копия. Одновременное редактирование в нескольких вкладках одного браузера не рекомендуется: используйте одну вкладку, особенно офлайн.

Текущая схема — для одного владельца, не система независимых пользовательских аккаунтов. Любой обладатель ключа сможет читать и менять данные этой базы. Отключение облака удаляет ключ только из текущего браузера, не отзывает его в других браузерах и не удаляет облачную базу. Резервная копия содержит ссылки и статистику — храните её отдельно, не в публичном репозитории.

Установка базы и тарификация описаны в [cloud/README.md](cloud/README.md).

Сводка складывает последние снимки счётчиков исходных публикаций; это не уникальные зрители и не одинаковое время наблюдения. Пустые поля сохраняются как неизвестные, а не нули. Переходы требуют отдельного источника отслеживания ссылок.

## Парсер
Сейчас есть ручной импорт JSON, а НЕ автоматический ежедневный сбор. Перед импортом привяжите точные URL к карточкам. Данные проверяются, неподходящие ссылки не привязываются по догадке. Повторяющиеся идентичные снимки не добавляются.

Будущая интеграция: адаптер существующей выгрузки → запуск парсера по расписанию на отдельном компьютере/сервере либо GitHub Actions при технической совместимости → защищённое хранилище → чтение сайтом. GitHub Pages сам не запускает Python и не имеет базы данных. Не публикуйте cookies, пароли, токены или резервные копии с приватными данными. Используйте разрешённые способы доступа и соблюдайте правила площадки.

Для одинакового сравнения полезны снимки около 24 ч / 72 ч / 7 дней после публикации. Один запуск в сутки не гарантирует точный 24-часовой замер.

Нет автопубликации, медицинской диагностики или назначения лечения. Псевдонимы/AI-аватары не следует выдавать за реальных медицинских специалистов.

## Обновление с версии 1
Формат резервной копии и ключ localStorage не изменены. На том же сайте в том же браузере данные сохранятся. При смене файла, домена или устройства сначала экспортируйте старую копию, затем импортируйте её в новую версию.

## Интеграция с предоставленным Threads Collector
Поддерживается архив links-v2 из версии `threads-collector-local` 1.0.0. Сам Collector изменять или переустанавливать не нужно.

1. В Collector соберите профиль в режиме «Ветки и статистика», включив «Обновить статистику…». Для поиска новых публикаций не включайте продолжение старой очереди.
2. На сайте один раз привяжите URL фактически опубликованного поста к его карточке: «Детали и статистика → Дата и ссылка».
3. Внизу сайта откройте «Дополнительные функции → Импорт из Collector» и выберите архив. Можно выбрать сразу несколько файлов разных аккаунтов.

Обычный путь архива на Mac: `~/Library/Application Support/Threads Collector/data/output/USERNAME/links-v2/archive.json`. В окне выбора файла macOS можно нажать Command+Shift+G и вставить путь.

Сайт разбирает JSON в браузере, не отправляя исходный архив на сервер. При подключённом облаке выбранные показатели, ссылки и история замеров сохраняются в личной базе вместе с отметками. Из архива берутся только счётчики исходного поста. Просмотры берутся только из подтверждённой шапки этого поста, не суммируются по продолжениям. Сохраняются времена отдельных показателей и признаки округления. Счётчики без времени наблюдения пропускаются, не получают вымышленную текущую дату. Авторские ответы не выдаются за независимые комментарии. Переходы не извлекаются из публичных просмотров. Идентичные замеры не дублируются. Частичные/устаревшие счётчики не следует принимать за новый полный сбор.

Дополнительный конвертер без сторонних зависимостей:
```
node integration/export-metrics.mjs /path/to/archive1.json /path/to/archive2.json --out /path/to/threads-metrics.json
```
Он экспортирует только выбранные числовые метрики и ссылки, без текстов, browser profile и cookies. Исходные архивы не изменяются.

### Что ещё НЕ подключено
Нет автоматического сбора, ежедневного запуска Collector или автоматической загрузки архивов с Mac на сайт. Облачная синхронизация сохранённых отметок и выбранных метрик доступна после подключения личной базы. Предоставленный Collector открывает локальный Chrome и требует подтверждения перед этапами сбора; его нельзя просто перенести в GitHub Pages. Живой прогон на пользовательских аккаунтах не выполнен. Для следующего этапа нужны фактические URL трёх профилей и согласованное место запуска/хранения статистики. На GitHub не размещайте `.browser-profile`, cookies, token-файлы или полные архивы.

## Проверки адаптера
```
node --test test/collector-adapter.test.mjs
```
Проверены корневые посты, разделение шапки/частей, неизвестное против нулевого значения, округление, времена показателей, пропуск неверного автора. Браузерные проверки выполнены на синтетических контрольных данных, не на живой сессии пользователя.


## Пополнение очереди без потери отметок
Посты загружаются из `posts.json` при открытии/обновлении сайта. При ошибке загрузки используется встроенная очередь. Обновление файла не синхронизирует личную статистику между устройствами.

Чтобы добавить посты: сохранить `kind: threads-content`, `version: 1`, всех трёх авторов и все существующие карточки; дописать новые с уникальными неизменяемыми ID (например A10, D10, E10), существующим person (A/D/E), целым day, slot и text не длиннее 500 символов. Не удалять старые карточки и не переиспользовать ID. Опубликовать изменённый posts.json в той же ветке и обновить страницу после завершения GitHub Pages. При добавлении новой партии допустимо также обновить встроенную очередь через build.py. Сначала экспортировать резервную копию.

Доступ к репозиторию позволяет ассистенту по запросу подготовить и добавить новую партию. Автоматического фонового пополнения и уведомления об окончании очереди сейчас нет.


## v4 — первый пост и продолжение

Карточка остаётся одной публикацией со стабильным ID. `text` — редакционно законченный первый пост (до 500 Unicode code points, включая пробелы и переносы); необязательный `continuation` — всё продолжение одним текстом, без ограничения 500 на весь блок. Длинный блок не разбивается сайтом и не публикуется автоматически. Владелец вставляет его ответом и проверяет автоматическое разбиение в редакторе Threads. Это рабочий процесс владельца, не гарантия поведения всех версий приложения.

На карточке два отдельно копируемых текста; у старых одиночных карточек — один. Нажатие или Enter/Space копирует соответствующий блок без заголовков и счётчика. Отметка «Опубликовано» относится ко всей ветке; её ставят после отправки обоих блоков. Метрики и URL относятся к исходному сообщению. Сохранены ключ localStorage, ID, старые тексты и схема version=1; поле continuation обратно совместимо. Не добавляйте продолжение к уже существующему опубликованному ID: создавайте новую карточку.

Пример новой карточки (не реальный контент очереди):
```json
{"id":"A_NEW_UNIQUE_ID","person":"A","day":4,"slot":"Утро","text":"Feed opener, deliberately ending at the right point.","continuation":"Full continuation copied in one action, even if longer than 500 characters."}
```


## v6 — время США и окно владельца 09:00–23:00 Москва

В карточках показывается московское время и эквивалент в Нью-Йорке и Лос-Анджелесе на дату из видимого поля «Пересчёт на дату». По умолчанию это сегодняшняя московская дата; ручной выбор сохраняется в дополнительном поле schedule_date резервной копии. День очереди не превращается автоматически в календарную дату. Сезонные смещения берутся из Intl.DateTimeFormat для America/New_York, America/Los_Angeles, Europe/Moscow, не из часового пояса браузера.

Исходные слоты: утро=09 ET, день=13 ET, прежний вечер=15 ET (в интерфейсе переименован в «День США», потому что вечер США недоступен без ночной публикации). Получается 16/20/22 МСК летом США и 17/21/23 МСК зимой. Примеры дня 4 используют 09 ET; дня 5 — 13 ET. Время одинаковое для трёх персонажей; это ориентиры, не обязательство нажать в одну минуту и не доказанные оптимумы. Не назначать действия позже 23 МСК; при задержке последнего слота пропустить/перенести, а не сдвигать за окно. Резерву время не назначается. Необязательное publish_hour_et позволяет задать новой карточке целый час 6–15 ET; все такие слоты остаются в допустимом московском окне в оба сезона.

Автопубликации, таймеров отправки и календарного назначения конкретных постов нет. Тексты, ID и статистика не изменяются.


## v8 — живое расписание и многочастная очередь (заменяет режим v6/v7 по умолчанию)

Верхний блок показывает текущие московские дату/часы (Intl, Europe/Moscow, время устройства). По умолчанию schedule_mode=auto; старое schedule_date без явно выбранного ручного режима игнорируется. Дата вводится только для предпросмотра; кнопка Авто возвращает текущие часы.

buildLivePlan распределяет очередь каждого персонажа по ближайшим свободным слотам 09/13/15 ET. План строится вперёд от текущей московской даты; текущий слот допускается ещё 15 минут, но не за 23:00 МСК. На отметке публикации в локальной записи сохраняется scheduled_slot с person и iso, чтобы не занять один слот дважды. Смена московского дня, пропущенные окна и DST пересчитываются автоматически. Группы очереди — реальные календарные даты, а исходный day остаётся порядком материалов в данных. При тиканье часов текст и статистика не меняются. Никакой отправки в Threads или таймера автопубликации нет.

Новые A12–A14/D12–D14/E12–E14: длинные тексты, batch=long-v2, hook_style=caps/emphasis/sentence. Всего в основной базе 15 длинных материалов. Прежние 24 коротких черновика без intro и continuation не занимают основной план и доступны в отдельной свёрнутой секции. Вернуть в план: локальный record.include_short=true. Три приветствия при необходимости остаются в плане, три резерва — отдельно. Уже опубликованные записи не скрываются из архива. Все старые text, continuation и ID сохранены.

Актуальный регрессионный тест: test-live-planner.cjs (в рабочей среде). Старые тесты до v8 могут ожидать прежнюю группировку по номерам дней и прежние подписи времени; это больше не текущий контракт интерфейса.


## v9 — минимальный интерфейс публикации (приоритет над v8)

Сверху только переключатель персонажей и маленькая строка текущей московской даты / Москвы / Нью-Йорка / Лос-Анджелеса. Нет кнопки авто, ручного выбора даты, описания следующего поста, дневных заголовков, ID, названий формата или инструкций копирования. Автоматический план остаётся включённым всегда, старый ручной режим не управляет им. В основной видимой очереди только сегодняшние посты, отсортированные по времени; будущие доступны в свёрнутом «Следующие посты» с короткой датой перед временем, чтобы не принять их за сегодняшние.

Карточка содержит только время, один или два копируемых текстовых блока и checkbox «Опубликовано». Удалена вся карточная форма «Детали и статистика». Сохранённые ссылки, история, отметки, импорт/экспорт резервной копии не удалены; общая статистика перенесена последним блоком вниз и свёрнута. Это изменение интерфейса, не миграция или очистка данных. Текст обоих блоков копируется полностью независимо от высоты просмотра. Смена московской даты входит в сигнатуру обновления плана, даже если абсолютные слоты до и после полуночи совпадают.
