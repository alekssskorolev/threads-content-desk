# Threads Desk

Версия 3: сверху персонажи и свёрнутая общая статистика по трём аккаунтам. Нажатие на текст копирует пост; увеличенная область «Опубликовано» перемещает карточку в нижний сворачиваемый раздел. Служебные кнопки скрыты под очередью.

Статический сайт без сборки и внешних библиотек: три автора, 27 публикаций на три дня + 3 резервных поста.

## Что работает
- Переключение авторов с адресами `#A`, `#D`, `#E`.
- Очередь неопубликованных постов в порядке дней, копирование нажатием на текст (с клавиатуры — Enter или пробел).
- Опубликованные посты находятся внизу. Резерв и Instagram bio — в дополнительных функциях.
- Отметка публикации, фактическое время и ссылка на пост.
- История измерений: просмотры, лайки, ответы, репосты, цитирования, поделиться, переходы.
- Резервные копии JSON и экспорт истории CSV.
- Прямой импорт одного или нескольких archive.json из Threads Collector links-v2; также поддерживается threads-metrics v1. Сопоставление по ID опубликованного поста. Формат: `parser-example.json`.

## Запуск
Откройте `index.html` в браузере. Для устойчивой работы буфера обмена и хранения рекомендуется HTTPS (GitHub Pages) или локальный HTTP-сервер. При запрете буфера используйте ручное выделение текста.

## GitHub Pages
1. Создайте публичный репозиторий, например `threads-content-desk`.
2. Загрузите `index.html`, `posts.json`, `.nojekyll`, `README.md`, `parser-example.json` в корень основной ветки.
3. Settings → Pages → Build and deployment → Source: Deploy from a branch.
4. Выберите основную ветку (обычно `main`) и папку `/ (root)`, затем Save.
5. Дождитесь завершения публикации. Адрес сайта GitHub покажет в Settings → Pages.

Никаких токенов и секретов в коде нет. Сайт публичный; любой посетитель может прочитать тексты постов.

## Хранение и приватность
Статистика и отметки находятся в localStorage браузера, а не на GitHub. Между устройствами они НЕ синхронизируются. Экспортируйте резервную копию и импортируйте на другом устройстве. Очистка браузера, приватный режим, смена домена или открытие локальной копии вместо сайта могут сделать прежние данные недоступными. Резервная копия содержит ссылки и статистику — храните её отдельно, не в публичном репозитории.

Сводка складывает последние снимки счётчиков исходных публикаций; это не уникальные зрители и не одинаковое время наблюдения. Пустые поля сохраняются как неизвестные, а не нули. Переходы требуют отдельного источника отслеживания ссылок.

## Парсер
Сейчас есть ручной импорт JSON, а НЕ автоматический ежедневный сбор. Перед импортом привяжите точные URL к карточкам. Данные проверяются, неподходящие ссылки не привязываются по догадке. Повторяющиеся идентичные снимки не добавляются.

Будущая интеграция: адаптер существующей выгрузки → запуск парсера по расписанию на отдельном компьютере/сервере либо GitHub Actions при технической совместимости → защищённое хранилище → чтение сайтом. GitHub Pages сам не запускает Python и не имеет базы данных. Не публикуйте cookies, пароли, токены или резервные копии с приватными данными. Используйте разрешённые способы доступа и соблюдайте правила площадки.

Для одинакового сравнения полезны снимки около 24 ч / 72 ч / 7 дней после публикации. Один запуск в сутки не гарантирует точный 24-часовой замер.

Нет автопубликации, медицинской диагностики или назначения лечения. Псевдонимы/AI-аватары не следует выдавать за реальных медицинских специалистов.

## Обновление с версии 1
Формат резервной копии и ключ localStorage не изменены. На том же сайте в том же браузере данные сохранятся. При смене файла, домена или устройства сначала экспортируйте старую копию, затем импортируйте её в новую версию.

## Интеграция с предоставленным Threads Collector
Поддерживается архив links-v2 из версии `threads-collector-local` 1.0.0. Сам Collector изменять или переустанавливать не нужно.

1. В Collector соберите профиль в режиме «Ветки и статистика», включив «Обновить статистику…». Для поиска новых публикаций не включайте продолжение старой очереди.
2. На сайте один раз привяжите URL фактически опубликованного поста к его карточке: «Детали и статистика → Дата и ссылка».
3. Внизу сайта откройте «Дополнительные функции → Импорт из Collector» и выберите архив. Можно выбрать сразу несколько файлов разных аккаунтов.

Обычный путь архива на Mac: `~/Library/Application Support/Threads Collector/data/output/USERNAME/links-v2/archive.json`. В окне выбора файла macOS можно нажать Command+Shift+G и вставить путь.

Сайт читает JSON локально в браузере, не отправляя архив на сервер. Из архива берутся только счётчики исходного поста. Просмотры берутся только из подтверждённой шапки этого поста, не суммируются по продолжениям. Сохраняются времена отдельных показателей и признаки округления. Счётчики без времени наблюдения пропускаются, не получают вымышленную текущую дату. Авторские ответы не выдаются за независимые комментарии. Переходы не извлекаются из публичных просмотров. Идентичные замеры не дублируются. Частичные/устаревшие счётчики не следует принимать за новый полный сбор.

Дополнительный конвертер без сторонних зависимостей:
```
node integration/export-metrics.mjs /path/to/archive1.json /path/to/archive2.json --out /path/to/threads-metrics.json
```
Он экспортирует только выбранные числовые метрики и ссылки, без текстов, browser profile и cookies. Исходные архивы не изменяются.

### Что ещё НЕ подключено
Нет автоматического сбора, ежедневного расписания, облачной синхронизации, автоматической загрузки данных с Mac на сайт. Предоставленный Collector открывает локальный Chrome и требует подтверждения перед этапами сбора; его нельзя просто перенести в GitHub Pages. Живой прогон на пользовательских аккаунтах не выполнен. Для следующего этапа нужны фактические URL трёх профилей и согласованное место запуска/хранения статистики. На GitHub не размещайте `.browser-profile`, cookies, token-файлы или полные архивы.

## Проверки адаптера
```
node --test test/collector-adapter.test.mjs
```
Проверены корневые посты, разделение шапки/частей, неизвестное против нулевого значения, округление, времена показателей, пропуск неверного автора. Браузерные проверки выполнены на синтетических контрольных данных, не на живой сессии пользователя.


## Пополнение очереди без потери отметок
Посты загружаются из `posts.json` при открытии/обновлении сайта. При ошибке загрузки используется встроенная очередь. Обновление файла не синхронизирует личную статистику между устройствами.

Чтобы добавить посты: сохранить `kind: threads-content`, `version: 1`, всех трёх авторов и все существующие карточки; дописать новые с уникальными неизменяемыми ID (например A10, D10, E10), существующим person (A/D/E), целым day, slot и text не длиннее 500 символов. Не удалять старые карточки и не переиспользовать ID. Опубликовать изменённый posts.json в той же ветке и обновить страницу после завершения GitHub Pages. При добавлении новой партии допустимо также обновить встроенную очередь через build.py. Сначала экспортировать резервную копию.

Доступ к репозиторию позволяет ассистенту по запросу подготовить и добавить новую партию. Автоматического фонового пополнения и уведомления об окончании очереди сейчас нет.
