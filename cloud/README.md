# Облачное хранение Threads Desk: установка в Яндекс Cloud

Это подготовка хранилища, а не включение синхронизации в текущем интерфейсе.
Сайт и существующие отметки в браузере на этом этапе не меняются.
После успешной установки нужен отдельный этап подключения сайта и переноса
отметок из браузера, в котором они сохранены. Сначала экспортируйте их резервную копию.

## Запуск

1. Войдите самостоятельно в [консоль Яндекс Cloud](https://console.yandex.cloud/).
2. Выберите нужный каталог и откройте Cloud Shell (терминал в консоли).
3. Загрузите `cloud/install.sh` из этого репозитория и запустите `bash install.sh`.
   В чате предоставляется готовая команда с закреплённым SHA коммита.
4. Проверьте показанный каталог и введите **ДА**, если согласны создать ресурсы.

Если каталог не выбран в CLI, скрипт покажет список и попросит его ID.
Авторизация в Cloud Shell должна уже работать. Скрипт не просит логин/пароль,
OAuth-токен, банковскую карту и не меняет CLI-профиль или платёжный аккаунт.
Нужен активный платёжный аккаунт и права создавать ресурсы, назначать
роль на создаваемую базу и разрешать публичный вызов создаваемой функции.

## Что создаётся

- **YDB Serverless**, не Dedicated, `ru-central1`: максимальное хранилище 1 GB,
  ограничение 50 RU/s, provisioned capacity = 0.
- **Cloud Function**, Python 3.12, 256 MB, тайм-аут 30 секунд, без логирования.
- **Сервисный аккаунт**: `ydb.editor` только на этой новой базе,
  без роли `editor` на весь каталог/облако.

Виртуальная машина, API Gateway, бакет и сервисный ключ доступа к облаку не создаются.
Функция обращается к базе через метаданные своего сервисного аккаунта.
База не открывается публично. HTTP-вызов функции публичный, но все операции с
данными проверяют отдельный случайный 256-битный ключ через заголовок `X-Desk-Key`.
В окружение функции передаётся SHA-256 ключа, не сам ключ.

CORS разрешает только `https://alekssskorolev.github.io`. Это **не замена** ключу:
любой небраузерный клиент может установить Origin. Не публикуйте ключ в исходниках.
Это однопользовательская схема, не полноценная система регистрации пользователей.
Она пока не предназначена для разных независимых владельцев/команд.

## Стоимость

YDB и Cloud Functions тарифицируются по использованию. Есть бесплатные пакеты,
но полная бесплатность не гарантируется: они могут уже использоваться другими
проектами. Лимиты RU/s и хранилища не являются денежным бюджетом.
Публичные вызовы, включая отклонённые до обращения к базе, могут тарифицироваться.

- [Тарифы YDB Serverless](https://yandex.cloud/en/docs/ydb/pricing/serverless)
- [Тарифы Cloud Functions](https://yandex.cloud/en/docs/functions/pricing)

## Проверки и результат

Установщик:
- создаёт таблицу `desk_state`, только если она отсутствует;
- пишет, читает и удаляет отдельную тестовую строку;
- проверяет отказ без ключа и с неверным ключом;
- проверяет CORS и чтение состояния с разрешённого сайта;
- не создаёт и не перезаписывает основную строку с пользовательскими отметками.

При успехе выводится `READY_ENDPOINT=https://functions.yandexcloud.net/...`.
Эту строку можно отправить в чат: это публичный адрес, не секрет.

**Секретный** `client-config.json` сохраняется в
`~/.threads-desk-cloud/<folder-id>/client-config.json` в личном хранилище Cloud Shell.
Установщик использует `umask 077` и пытается ограничить права папки. Если
файловая система Cloud Shell не поддерживает `chmod`, он сообщает об этом
и продолжает без изменения прав. В этом случае POSIX-права не гарантируются;
не предоставляйте другим людям доступ к своей сессии и домашней папке Cloud Shell.
Файл понадобится для подключения сайта. Не отправляйте его в чат, не публикуйте
на GitHub и не присылайте скриншоты с его содержимым. Не удаляйте папку установки.

Повторный запуск использует сохранённые ID ресурсов и тот же ключ, заново
развёртывает функцию и повторяет проверки. Если создание уже завершилось в
облаке, но Cloud Shell прервался до сохранения ID, возможна ошибка совпадения имени;
в таком случае сообщите текст ошибки без секретов, а не удаляйте базу вручную.
После ошибки ресурсы могут остаться и продолжать тарифицироваться.

## Удаление

Путь к `remove.sh` выводится после успеха. Запуск отдельно запрашивает слово
`УДАЛИТЬ`, затем удаляет **функцию, базу со всеми облачными отметками и сервисный аккаунт**.
Локальные отметки сайта и конфиги Cloud Shell не удаляются. Перед удалением
обязательно экспортируйте актуальные отметки. Случайное удаление через установщик
не выполняется; автоматического отката с уничтожением данных нет.

## Контракт будущего подключения

POST, JSON, заголовок `X-Desk-Key`. Ответы — JSON, `Cache-Control: no-store`.

- `{"op":"get"}` → `{"revision":0,"state":null}` для пустой базы.
- `{"op":"put","expectedRevision":0,"state":{"kind":"threads-desk-backup","version":1,"records":{}}}`
  → `{"revision":1}`.
- Устаревшая ревизия → HTTP 409, без перезаписи данных.
- `{"op":"init"}` → создание таблицы при отсутствии и проверка тестовой строки.
- Неверный ключ → 401; посторонний Origin → 403; некорректные данные → 400;
  слишком большой запрос → 413; ошибка хранилища → 503 без внутренних деталей.

Транзакция сравнивает ревизию и записывает новое состояние атомарно. Это защита
от тихой потери изменений при открытии двух браузеров. Будущий клиент должен
обрабатывать 409, не отправлять устаревшее состояние автоматически при старте и
предлагать перенос локальных отметок при первом подключении к пустой базе.
Максимальный запрос — 512 000 байт. Для большого архива метрик потребуется другая
схема; для небольшого текущего состояния достаточно одной строки.
